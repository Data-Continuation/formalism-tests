# Build Stage Docs-to-Docs Policy Bundle

## Assumptions

1. Build-stage generated documentation belongs under `docs/`.
2. Root should not accumulate stage-specific markdown or duplicate theorem-map fragments.
3. Cleanup should be governed, report-first, and non-destructive.
4. The task in this bundle reports and plans. It does not move or delete files.
5. No leading-dot workflow path is included in this bundle.

## Done

This bundle is done when the repo contains:

```text
data/build_stage_output_policy.json
docs/policies/build-stage-output-placement-policy.md
docs/roadmaps/root-documentation-canonicalization-plan.md
tools/enforce_build_stage_output_paths.py
tools/tasks/build_stage_output_policy_tasks.json
```

and the task emits:

```text
reports/build_stage_output_path_policy_report.json
reports/root_doc_canonicalization_plan.json
receipts/build_stage_output_path_policy_receipts.jsonl
```

## Task ID

```text
enforce_build_stage_output_paths
```

## Run

```bash
python tools/run_declared_tasks.py tools/tasks/build_stage_output_policy_tasks.json --task-id enforce_build_stage_output_paths
```

## Policy Rule

```text
Build-stage processes must place generated documentation under docs/, not at repository root.
```

## Root Markdown Rule

Allowed root markdown:

```text
README.md
```

Everything else generated by stage builds should live under:

```text
docs/stages/
docs/theorem/
docs/indexes/
docs/roadmaps/
docs/site/
docs/legacy/
docs/policies/
```

## Boundary

```text
Report first.
Plan moves second.
Do not delete.
Do not overwrite canonical docs without explicit review.
```
